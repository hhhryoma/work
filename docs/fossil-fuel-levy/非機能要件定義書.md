# 非機能要件定義書(ドラフト)

- 位置づけ: 業務仕様書 §6.3 の8項目を要件レベルへ展開。目標値は**業務量前提が未確定のためすべて仮置き**(政省令確定・事業者数確定後に見直し)
- 参考フレーム: IPA非機能要求グレード

## 0. 業務量の前提(仮置き — 最重要の見直し対象)

| 項目 | 仮置き値 | 根拠 |
|---|---|---|
| 対象事業者数 | 〜500社 | 石油石炭税の納税義務者数オーダーからの類推(要実数確認) |
| 申告件数 | 月次×500社=6,000件/年 | 期別は月次仮置き |
| 申告明細・実績明細 | 1申告あたり明細〜10行、実績〜5,000行 | 大手輸入者のCSV規模想定 |
| 納付完了情報 | 日次〜1,000件(ピーク: 納期限翌営業日) | |
| 還付事案 | 〜500件/年 | 過納+用途の合算想定 |
| 同時利用 | 事業者ポータル〜200、内部〜50 | 申告期限直前ピーク |

## 1. 可用性

| 項目 | 要件(仮) |
|---|---|
| サービス時間 | ポータル: 平日・休日 8:00〜24:00 / 内部: 平日 8:30〜19:00 |
| 稼働率 | 99.5%(サービス時間内) |
| RPO/RTO | RPO=1時間(申告・納付データ)/RTO=4時間 |
| 期限日特例 | 申告期限日・納期限日に障害が発生した場合の**期限延長の運用ルール**を機構規程として整備(システムでの期限日変更操作を含む) |

## 2. 性能・拡張性

| 項目 | 要件(仮) |
|---|---|
| オンライン応答 | 通常画面 3秒以内(95%ile)/検索・集計 10秒以内 |
| CSV取込 | 実績明細5,000行を5分以内(非同期+進捗表示) |
| バッチ窓 | IF-1a取込〜消込〜受信結果応答を 7:00〜9:00 の2時間以内 |
| ピーク設計 | 申告期限日の同時申告(500社の7割が最終3日に集中と想定)に耐えること |
| 拡張性 | 事業者数2倍・特定事業者負担金(2033年度〜)の同居をスケールアップで吸収可能な設計 |

## 3. セキュリティ

| 項目 | 要件 |
|---|---|
| 準拠基準 | 政府情報システムに準ずる整理を想定: 政府統一基準群、クラウド利用時はISMAP登録サービス(機構の位置づけに応じ要確認) |
| 認証 | 事業者=GビズID(第一候補)+多要素/内部=職員ID+多要素。代理申告(委任)は権限モデル確定後 |
| アクセス制御 | 職務分掌: **起案者と承認者の分離をシステムで強制**(決裁ワークフロー)。還付支払と口座変更承認の兼務禁止 |
| 暗号化 | 通信TLS1.2以上、保存データ暗号化、IF転送ファイルの暗号化(方式は経産省協議) |
| 監査証跡 | 金額に関わる全操作(入力・承認・マスタ変更・還付支払)の操作ログを改ざん検知つきで7年保存 |
| 個人情報 | 代表者氏名・口座情報等の最小限。マスキング表示(口座は下4桁等) |

## 4. 運用・保守

| 項目 | 要件 |
|---|---|
| 監視 | IF未達(定刻+2時間)、バッチ異常、消込エラー滞留、還付支払不能をアラート。**受信結果応答(R11)は自動生成**であり職員判断を要しない(9:00応答SLAと内部業務開始8:30は矛盾しない)。E03保留等のエラー実対応は業務時間内に行う |
| バックアップ | 日次フル+時間毎差分。年度末・政省令改定前は世代を追加保全 |
| パラメータ運用 | 期別・期限・利率・単価・係数・決裁閾値は**設定変更のみで反映**(リリース不要)。変更は承認つき+適用開始日指定+履歴保持 |
| 年度切替 | 単価・係数の新年度世代登録→検証環境での計算検証→本番反映、の年次運用を定義 |
| リリース | 政省令対応期(2027年度後半)は月次リリース枠を確保 |

## 5. 移行・データ保存

| 項目 | 要件 |
|---|---|
| 初期移行 | 制度開始前の一斉届出(〜500社)の受付・審査体制。GX-ETSの事業者マスタが共用可能なら初期取込を検討(課題#19) |
| 保存期間 | 申告・証憑・通知書・監査ログ: 7年(帳簿保存義務との整合。確定は政省令待ち)。期間経過後はアーカイブ層へ |
| 帳票基盤 | 通知書PDF生成はテンプレート版管理(様式改定に改修なしで追従) |

## 6. 未確定・見直しトリガー

1. 業務量前提(§0)は事業者数・期別の確定で全面見直し
2. ISMAP等の準拠要否は機構システムの制度上の位置づけ確定後
3. 認証方式(GビズID)は機構方針決定後(課題#18)
4. IF関連のSLA(未達判定・再送)は経産省協議(課題#8)の結果を反映
