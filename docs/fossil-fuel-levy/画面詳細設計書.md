# 画面詳細設計書(ドラフト)

- 位置づけ: 業務仕様書 §3 の画面一覧を詳細設計レベル(項目定義・チェック・アクション)へ展開。**暫定想定集.md を正**として記述(想定変更時はパラメータ/本書の該当箇所を追随)
- 画面イメージ: 別紙HTMLモック2式に対応。本書は項目・挙動の定義を担う

## 0. 共通仕様

### 0.1 ロールと認証

| ロール | 認証 | 主な画面 |
|---|---|---|
| 事業者-管理者 | GビズIDプライム | P系全部+委任管理 |
| 事業者-担当者 | GビズIDメンバー | P系(委任範囲内) |
| 事業者-委任先(通関業者等) | GビズID+委任届出(#18/#45: 資格不問の届出制) | 委任された申告・申請のみ |
| 機構-審査担当 | 職員ID+多要素 | G-1〜G-4 |
| 機構-収納担当 | 同上 | G-1, G-5 |
| 機構-還付担当 | 同上 | G-1, G-6 |
| 機構-制度担当 | 同上 | G-7 |
| 機構-決裁者(課長/部長/理事) | 同上 | 決裁対象画面(参照+承認/差戻しのみ) |
| 機構-システム管理者 | 同上 | 全画面(ユーザ・権限管理) |

- **職務分掌の強制**: 起案者=承認者の操作をシステムで拒否。還付支払の決裁者と口座変更届出の承認者の兼務を禁止
- **口座変更90日ルールの役割分担**: P-2(事業者が変更届出)→G-2(機構が承認時に確認記録を作成。90日フラグ起算)→G-6(還付の支払前チェックでフラグと確認記録を**参照**。記録がなければ支払決定をブロック)。実装は1機能で、画面ごとの役割は発生/記録/参照に分かれる
- 排他制御: 楽観ロック(更新番号)。同一対象の同時決裁は後勝ち拒否

### 0.2 入力チェックの4層

1. 単項目: 必須/型/桁/コード存在(画面即時)
2. 相関: 項目間整合(例: 控除数量≦数量)(画面即時)
3. 業務: マスタ・状態との整合(例: 対象申告が「確定」か)(送信時)
4. 重複・不正: 二重申請、用途証明書の重複、期限超過(送信時)

エラー表示規約: 項目直下に赤字で「何が・なぜ・どうすれば」を記載(例:「控除数量が数量を超えています。控除数量は12,000.000 kL以下で入力してください」)。

### 0.3 表示規約

- 金額: カンマ区切り・円/数量: 小数3桁・単位併記/等幅数字
- 状態: 状態遷移定義.md の状態名をピル表示。色グループの対応: **緑(完了系)**=完納・受理・支払済・履行完了/**黄(進行系)**=提出済・審査中・照会中・一部納付・延納中・申請/**赤(要対応系)**=差戻し・未納(期限超過)・過納検知・停止・支払不能・許可取消/**青(確定系)**=確定・額確定・認容・許可・振込データ作成/**グレー**=下書き・取下げ・却下・時効消滅・欠損・廃止
- 日付: YYYY-MM-DD。期限系は残日数を併記(30日以内は黄、7日以内は赤)
- 一覧: 50件/頁、既定ソートは要対応→更新日降順

### 0.4 監査ログ

金額・状態・マスタ・口座に関わる全操作(参照除く)を「いつ・誰が・どの画面で・何を・変更前後値」で記録。改ざん検知(ハッシュチェーン)。保存7年(#13)。

### P-2 届出(F01)

主な項目(F01の項目定義に準拠。画面固有の制御のみ記載):

| 項目 | 制御 |
|---|---|
| 届出区分 | 新規/変更/廃止/**承継**(#42: 合併・分割・事業譲渡・相続。承継元事業者番号+承継日を追加入力) |
| 法人番号 | 「国税庁照合」ボタン→IF-3で実在性・名称一致を即時確認(API停止時は「後日確認」で受付継続) |
| 還付先口座 | 変更時は名義カナの自動照合。**変更受理から90日間は還付時に追加確認フラグ**(G-6のガード) |

チェック: 廃止届出時に未納債権・進行中還付があれば警告(受付は可、完結まで論理削除しない)。
アクション: 下書き保存/確認画面へ/提出(→NT番号採番、G-2ワークリストへ)。

### P-3 賦課金申告(F02+F03)

ウィザード: ①対象期間 → ②実績取込 → ③明細確認 → ④確認・提出

| 項目 | 定義・制御 |
|---|---|
| 対象年度・期 | 月次(#4)。未申告の最古期を初期表示。提出済みの期は選択不可(訂正は期限内のみ再提出可) |
| 実績CSV(F03) | 非同期取込(5,000行/5分以内)。行単位エラーはダウンロード可能なエラーリストで返却(行番号+理由)。取込結果: 総行数/正常/エラー |
| 明細(燃料種別別に自動集計) | 燃料種別/数量・単位/CO₂係数(マスタ自動・変更不可)/控除数量(国内非使用見込・**バンカー油等の非賦課数量は別区分**#31)/**戻入れはマイナス明細**(#33)/賦課対象CO₂量/賦課金額 |
| 適用単価 | 対象期の年度単価をマスタ参照・変更不可。「※政令(令和XX年政令第XX号)」を注記 |
| 合計 | 賦課対象CO₂量合計・賦課金額合計(端数: 課税標準1,000円未満切捨て→税額100円未満切捨て #34) |

チェック(相関・業務): 控除数量≦数量/マイナス明細は同一燃料種別の正数量の範囲内/申告期限超過時は警告(受付は可・遅延理由入力)/F03合計数量と明細集計の一致(許容誤差±0.5% #35)。
アクション: 下書き保存/提出(→LV番号採番、受付通知R02を即時交付、G-3ワークリストへ)。

### P-4 申告・納付状況照会

| 一覧項目 | 申告番号/年度期/申告額/納付済額(経産省連携の消込結果)/納期限(延納反映後)/状態(未納・一部納付・完納)/延滞金(確定分) |
|---|---|

備考: 納付手続き自体は本ポータル対象外である旨を常時表示。納付は経産省発行の**納入告知書(窓口)またはペイジー電子納付**による旨を案内(ADAMS前提・IF仕様書§6)。**納付情報の反映には収納から数営業日かかる**注記を常設し、期限直前納付の未納誤検知を防ぐ猶予日数パラメータ(§4)を適用。

### P-5 還付メニュー/申請(F04・F05)

- メニュー: 過納還付(更正の請求)/用途還付 の2カード(モック画面A)
- **F04 更正の請求**: 対象申告(確定済のみ選択可)/当初額(自動)/正当額(入力)→過納額自動計算/理由区分・詳細(必須)/証憑添付(必須)/還付先口座(届出口座を初期表示)
  - チェック: 正当額<当初額(増額方向は修正申告不可の注意文言を表示し受付拒否→期限内訂正または機構へ照会を案内)/請求期限(法定納期限から5年 #6)
- **F05 用途還付申請**: 対象申告(**納付済のみ**選択可)/燃料種別/用途区分(2区分 #7)/数量/用途に供した日(期限起算・1年以内 #7仮)/使用者(用途証明発行者)の法人番号・名称/用途証明書番号/還付請求額(数量×係数×**納付年度単価** #25、納付済額上限)/石油石炭税還付の併用有無/証憑(用途証明必須)
  - チェック: **用途証明書番号の重複・残数量**(C8。同一番号の申請済数量+今回数量≦証明書数量)/数量≦当該申告の対象数量
- アクション: 下書き/取下げ(審査着手前)/提出(→RF番号採番)

## 2. 内部業務画面(G系)

### G-1 業務ダッシュボード

KPI定義(算出式を固定):

| KPI | 算出 |
|---|---|
| 審査待ち申告 | 状態=提出済・審査中 の件数 |
| 差戻し・照会中 | 状態=差戻し・照会中 の件数(7日超過は赤) |
| 未申告事業者 | 有効事業者のうち当期申告なし かつ 期限超過 |
| 還付支払待ち | 還付状態=額確定・振込データ作成 の件数 |
| 当期収納率 | 当期完納債権額 ÷ 当期賦課決定額(取消・更正反映後) |

ワークリスト: 要対応(差戻し期限超過/突合NG/過納検知/連携エラー/決裁待ち)を優先度順に集約。行クリックで各画面へ。

### G-2 事業者管理

- 検索: 事業者番号/法人番号/名称(部分一致)/状態/事業者区分(納付・非納付・証明機関 #23/#26)
- 詳細タブ: 基本情報/届出履歴(審査アクション含む)/申告・収納状況/還付先口座(**世代履歴+90日フラグ**)/関連書類/承継関係(#42: 前身・後継のリンク)
- 届出審査: 承認(→受理・R01交付。新規は事業者番号採番)/差戻し。口座変更の承認者は還付支払決裁者と兼務不可(0.1)

### G-3 申告審査

- ワークリスト+審査詳細(モックどおり)
- 自動チェック結果: 形式/係数・単価一致/F03突合(誤差±0.5%超を行ハイライト)。NACCS突合は**Phase 2**(#12。当面は報告徴収ベースの事後確認)
- アクション: 承認(→申告確定・債権発生・納付番号採番・IF-1o連携キュー投入・R02確定版)/差戻し(R08)/照会(期限つき。回答期限超過はワークリストへ再浮上)
- 無申告処理: 未申告抽出リストから職権決定の起案(G-4)へ連携

### G-4 賦課金額決定・更正

- タブ: 更正(請求に基づく)/更正(職権)/決定(無申告)
- 表示: 当初/更正後/差額(CO₂量と金額)。請求起点の場合は F04 内容と証憑を並列表示
- 決裁ルート: 金額閾値パラメータ(#20: 課長500万/部長1億/理事以上。不利益処分は部長以上)で自動決定。トラッカー表示
- 確定時処理: 減額→過納検知判定→還付起票(G-6)/増額→債権残高洗い替え(#22)+IF-1o変更連携/通知書(R03〜R05)交付予約(交付日=掲載日)
- チェック: 対象申告が確定済/同一申告に対する未完了の処分が存在しないこと(多重更正防止)

### G-5 収納状況管理

- 取込結果: ファイル単位(検証結果・件数・エラー内訳)。**手動アップロード**(障害時代替、要決裁)
- 消込一覧: 検索(事業者/期/状態)。過納検知行は還付案内アクション(G-6起票済みならリンク)
- 保留トランザクション(E03): 賦課決定前入金の滞留一覧。精算(紐付け)/返戻の操作(要決裁)
- 延滞金: 納付日確定時に自動計算(率パラメータ #6同様仮: 納期限後2か月まで年2.4%・以降年8.7%)。免除(災害延長 #38)は一括操作+決裁
- 期限一括延長(#38): 対象抽出(地域・事業者指定)→新期限入力→決裁→納期限上書き+IF-1o変更連携

### G-6 還付審査・支払管理

- ワークリスト: 種別(過納/用途)・起票元(自動/申請)・状態別
- 審査詳細: 前提処分の状態(過納は減額更正の確定を必須ガード)/支払前チェックリスト(**自動判定+目視確認のハイブリッド**):
  1. 充当判定: 同一事業者の未納債権・延滞金を自動検索→充当案を自動作成(充当順序: 延滞金→本体・古い順)。承認で充当記録作成
  2. 口座: 有効世代か/**変更後90日以内は追加確認**(G-2の確認記録が必要)
  3. 二重支払: 同一処分・同一証明書番号の既払い検索
- 加算金: 自動計算(元本×0.9%×日数/365 #6。起算=納付日翌日、終了=支払決定日)。計算根拠を画面表示・通知書(R07)へ転記
- 決裁: 支払決定(閾値ルール #20)→振込データ作成(全銀・バッチB05)→支払結果取込(B06)→支払済(R07交付)
- 停止制御: 対象納付番号への取消レコード受信で自動停止+アラート。再開は手動+決裁
- 不正還付の取戻し(#40): 支払済み事案からの「返還請求起案」→還付返還債権の発生(G-4決裁ルート準用)

### G-7 マスタ管理

タブ: 賦課金単価(年度・政令番号・適用期間)/CO₂係数(燃料種別×適用期間)/燃料種別/用途区分/**営業日カレンダー**(#37)/**業務パラメータ**(§4)
- 変更は承認つき+適用開始日指定+履歴保持。適用中世代の直接変更は禁止(新世代を作成)
- 年度切替(#28): 新年度単価の登録→検証環境計算検証→承認→適用のチェックリストを画面内に表示

### G-8 延納審査・担保台帳【候補・初期リリース外 #10】

初期は台帳を簡易管理(スプレッドシート相当の登録画面のみ検討)。本格実装は2029年度。
