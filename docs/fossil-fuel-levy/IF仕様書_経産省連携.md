# インターフェース仕様書(ドラフト): 経産省連携

- 対象システム: 化石燃料賦課金管理システム(GX推進機構) ⇄ 経産省(収納側)
- 作成日: 2026-07-09
- 位置づけ: 業務仕様書 6.2 IF-1 の詳細化。**連携方式・項目は経産省との協議前の機構側たたき台**

## 0. 連携の全体像

納付書発行・督促状発行は本システム対象外、納付完了情報は経産省から連携される前提。この前提を成立させるには、**下り(経産省→機構)だけでなく上り(機構→経産省)の連携が論理的に必須**になる点が本仕様書の最重要論点である。

| IF-ID | 方向 | 内容 | 頻度 | 状態 |
|---|---|---|---|---|
| IF-1o | 機構→経産省 | **賦課決定情報**(請求情報。収納側が入金を紐づけるための元データ) | 日次 | **論点**(後述 §4) |
| IF-1a | 経産省→機構 | **納付完了情報**(F06) | 日次 | 前提済み・仕様協議要 |
| IF-1b | 経産省→機構 | **延納許可情報** | 随時(日次便に相乗り) | 候補(延納許可主体が収納側の場合のみ) |

```
機構                                     経産省(収納側)
 │ IF-1o 賦課決定情報(納付番号・額・期限) ──▶ 収納受入準備
 │                                            (事業者が納付 ※本システム外)
 │ ◀── IF-1a 納付完了情報(納付日・額・取消) │
 │ ◀── IF-1b 延納許可情報【候補】           │
 ▼ 消込・延滞金確定・過納検知
```

## 1. 共通仕様(全IF共通)

### 2.2 取込処理フロー

1. ファイル検証(命名・連番・トレーラ件数/金額合計)→ NGはファイル単位で取込保留
2. レコード単位チェック(§2.3)→ エラーレコードはスキップし、正常分のみ取込(部分成功方式)
3. 消込: 納付番号で賦課決定(債権)と突合し、納付区分ごとに充当
4. 状態更新: 未納 → 一部納付 → 完納。**納付額合計 > 債権残高なら「過納検知」**とし還付業務(E-1)のワークリストへ自動連携
5. 延滞金の確定: 納付日をもって延滞金を確定計算(納期限翌日〜納付日。率は政省令待ちのパラメータ)
6. 受信結果応答: 正常件数・エラー明細(§2.3のコード付き)を返送

## 4. IF-1o 賦課決定情報(機構→経産省)【論点・最重要】

### 4.1 なぜ必要か

収納側が入金を賦課決定に紐づけるには、**請求(いくら・誰が・いつまでに・どのキーで)の事前情報が必須**。納付書発行は対象外だが、「納付書を作らない」ことと「請求情報を連携しない」ことは別問題であり、以下のどちらかを協議で決める必要がある:

- **案A(推奨)**: 機構が納付番号を採番し、IF-1oで賦課決定情報を日次連携。経産省は納付番号で収納受入 → IF-1aで同じ納付番号を返す。**消込が機械的に完結**
- **案B**: 経産省側が独自キーで収納し、機構は事業者番号+金額等で名寄せ消込。**曖昧マッチングが発生し消込エラーが常態化するため非推奨**

### 4.2 レコードレイアウト(案A前提)

| # | 項目 | 型・桁 | 必須 | 内容 |
|---|---|---|---|---|
| 1 | 連携ID | C(20) | ◎ | 機構側採番 |
| 2 | 処理区分 | K(1) | ◎ | 1:新規 2:変更(更正による金額変更) 3:取消(減額更正で0円等) |
| 3 | 納付番号 | C(16) | ◎ | 機構採番。以後の全連携の消込キー |
| 4 | 事業者番号・事業者名 | C(10)/C(120) | ◎ | |
| 5 | 対象申告/決定番号 | C(14) | ◎ | |
| 6 | 賦課金額(請求額) | N(15) | ◎ | 更正時は更正後残高 |
| 7 | 納期限 | D | ◎ | 延納許可(機構側許可の場合)反映後の期限 |
| 8 | 発生事由 | K(1) | △ | 1:申告 2:職権決定 3:増額更正 |

### 4.3 更正・還付との整合

- **増額更正**: 処理区分2で差額分の請求情報を連携(または残高洗い替え。方式は協議)
- **減額更正**: 納付済額が新残高を超える場合、機構側で過納検知→還付(E-1)。**収納側への返金指示は流さない**(還付は機構が全銀IF-5で直接支払うため)。二重返金防止の責任分界を協議で明文化すること
- **資金決済**: 本仕様書はデータ連携のみを対象とする。経産省が収納した資金を機構の還付原資・GX経済移行債償還原資へ充当する**資金そのものの振替スキーム**(国庫金/機構口座への経路・頻度・残高照合)は別途協議が必要

## 6. ADAMS(官庁会計システム)前提での具体化【仮説・協議のたたき台】

収納側が経産省の**官庁会計システム(ADAMSⅡ)**である前提が置けた場合、本仕様書の論点の多くが以下のとおり具体化する。

### 6.1 モデルの再定義: 「賦課決定情報」→「調定連携」

```
機構(債権確定)                経産省 歳入徴収官(ADAMS)              事業者
 │ IF-1o 調定依頼(債権キー・額・期限) ──▶ 調定 → 納入告知書の発行 ──▶ 受領
 │ ◀── 採番結果返送(納入告知書番号等) │
 │                                    (窓口納付 or REPS/ペイジー電子納付)
 │ ◀── IF-1a 収納済通知データ(日銀収納日・額) │
 ▼ 消込・延滞金確定・過納検知
```

- **「納付書発行はシステム対象外」の根拠が確定する**: 納付書=納入告知書の発行主体はADAMS(経産省歳入徴収官)。機構側は発行機能を持たなくてよい
- **採番主体論点(課題#1)は案Aの変形「案A'」が最有力に**: 消込キーはADAMS側で採番される**納入告知書番号(+REPSの収納機関番号・納付番号・確認番号)**。機構は債権キー(納付番号)を添えて調定依頼し、**採番結果の返送**を受けて対応表を保持する。IF-1oは「調定依頼+採番結果返送」の往復IFになる
- 通知書(R03/R04)には機構の納付番号でなく「納入告知書が別途送付される」旨を記載する形が有力(帳票定義 課題#14の方向性)

### 6.2 IF-1aの具体化: 収納済通知データ準拠

- レイアウトはADAMSの収納済通知データの項目(納入告知書番号・収納日・収納金額・収納機関等)に寄せて再定義する
- **納付日=日銀収納日**。収納済通知の機構への到達には**数営業日のラグ**があるため、①P-4の表示に「納付情報の反映には数営業日かかります」を明記、②延滞金計算は収納日基準(反映遅延と区別)、③期限直前納付の「未納誤検知」を防ぐ猶予日数パラメータを追加
- 取消レコードは ADAMS の**過誤納整理・返納**の実務に対応づける(協議で用語・コードを揃える)

#### 6.2.1 推定項目マップ v0.9(公開情報ベース。正式レイアウト入手までの暫定)

ADAMSの連携仕様自体は非公開のため、法令・日銀規程・ペイジー(MPN)公知情報から**再構成可能な範囲(約4〜5割)**を項目ごとに整理する。電子納付の経路は「受付システム→REPS(歳入金電子納付)→MPN→ADAMS」であることが公開資料で確認済み。

| **確認番号**【追加候補】 | 同上(電子納付時の照合キー) | 同上 | 高 |
| 納付日 | 領収済通知の収納日時(日銀→収納機関) | 日銀 国庫金電子収納事務取扱手続・統合国庫記帳システム留意事項 | 高 |

| 収納チャネル | 窓口(納入告知書)/ペイジー電子納付の2系統 | 日銀・e-Gov公開資料 | 中 |

### 6.3 延滞金の計算主体【新論点 → 課題#50】

納入告知書ベースの収納では、延滞金を「告知額に含める(ADAMS側計算)」か「機構が確定計算し追加調定を依頼する」かの分岐がある。e-Gov電子納付には期限超過時の延滞金自動計算の仕組みがあり、ADAMS側計算に寄る場合はIF-1aの納付区分(本体/延滞金)の意味付けと機構側計算エンジンの役割が変わる。**どちらでも対応できるよう、機構側の延滞金計算は「確定計算」と「検算」の両モードを想定**しておく。

### 6.4 消込の責任分界: マッチングはADAMS、債権充当は機構

ADAMS前提では「消込」を2層に分けて整理する。

| 層 | 担当 | 内容 |
|---|---|---|
| マッチング(入金と請求の突合) | **ADAMS** | 調定・納入告知書番号に収納済通知が1:1で紐づいた状態で連携される。機構での名寄せ・曖昧マッチングは不要(案Bの消込エンジンは廃案にできる) |
| 債権充当(残高・状態の更新) | **機構** | 賦課金は法律上機構の債権であり、更正・延滞金・過納検知・還付充当という債権を動かすイベントはすべて機構側にある。ADAMSはこれらを知らないため、債権台帳への充当記帳は機構の責務として残る |

機構側実装への簡素化効果: ①E03(賦課決定前入金)はほぼ消滅(告知書なしに納付不可)し防御的チェックに格下げ ②納入告知書は原則全額納付のため「一部納付」は分割調定時のみに限定 ③過納検知の主経路は「納付済み後の減額更正」に一本化 ④B01は突合処理でなく「取込→充当記帳→後続イベント発火」の単純パイプラインになる。
逆に新たな責務: **債権を動かしたら調定側を同期させる**こと(更正・延納時のIF-1o処理区分2=調定変更依頼)。機構帳簿とADAMS/国庫の月次残高照合(§5)は二重帳簿の整合確認として維持する。

### 6.5 資金決済(#9)の整理の具体化

ADAMS収納は国庫(国の歳入)への収納となるため、法律上**機構の収入**である賦課金を国庫経由で受け入れる法的整理(歳入代理・歳入外現金・国庫からの定期振替のいずれか)が必要になる。データ連携とは別建てで、財務・会計部門間の協議事項として明確化された。
