# インターフェース仕様書(ドラフト): 経産省連携

- 対象システム: 化石燃料賦課金管理システム(GX推進機構) ⇄ 経産省(収納側)
- 作成日: 2026-07-09
- 位置づけ: 業務仕様書 6.2 IF-1 の詳細化。**連携方式・項目は経産省との協議前の機構側たたき台**

## 0. 連携の全体像

納付書発行・督促状発行は本システム対象外、納付完了情報は経産省から連携される前提。この前提を成立させるには、**下り(経産省→機構)だけでなく上り(機構→経産省)の連携が論理的に必須**になる点が本仕様書の最重要論点である。

| IF-ID | 方向 | 内容 | 頻度 | 状態 |
|---|---|---|---|---|
| IF-1o | 機構→経産省 | **賦課決定情報**(請求情報。収納側が入金を紐づけるための元データ) | 日次 | **論点**(後述 §4) |
| IF-1a | 経産省→機構 | **納付完了情報**(F06) | 日次 | 前提済み・仕様協議要 |
| IF-1b | 経産省→機構 | **延納許可情報** | 随時(日次便に相乗り) | 候補(延納許可主体が収納側の場合のみ) |

```
機構                                     経産省(収納側)
 │ IF-1o 賦課決定情報(納付番号・額・期限) ──▶ 収納受入準備
 │                                            (事業者が納付 ※本システム外)
 │ ◀── IF-1a 納付完了情報(納付日・額・取消) │
 │ ◀── IF-1b 延納許可情報【候補】           │
 ▼ 消込・延滞金確定・過納検知
```

## 1. 共通仕様(全IF共通)

| 項目 | 仕様(案) |
|---|---|
| 連携方式 | 閉域網(政府共通NW等)経由のSFTPファイル連携を第一候補。代替: 相互認証付きREST API |
| ファイル形式 | CSV、UTF-8(BOMなし)、改行CRLF、ダブルクォート囲み |
| レコード構成 | ヘッダ(H)+データ(D)×n+トレーラ(T)。トレーラに件数・金額合計を持ち受信側で検証 |
| ファイル命名 | `<IF-ID>_<送信元>_<YYYYMMDD>_<連番3桁>.csv` 例: `IF1A_METI_20280810_001.csv` |
| 連番管理 | 日単位の連番。**欠番検知**(前回受信連番+1でない場合はアラート・取込保留) |
| 0件連携 | 対象0件でもヘッダ+トレーラのみのファイルを送る(未達との区別のため) |
| 冪等性 | 全レコードに一意の連携IDを付与。**同一連携IDの再取込はスキップ**(再送安全) |
| 暗号化 | 閉域網の場合も転送ファイルはPGP等で暗号化(協議事項) |
| スケジュール(案) | 経産省側 前日分締め→6:00送信/機構側 7:00取込→9:00までに受信結果応答(正常件数・エラー明細) |
| 障害時 | 定刻+2時間で未達ならアラート→両者連絡。手動アップロード画面による代替取込を用意 |

## 2. IF-1a 納付完了情報(経産省→機構)

### 2.1 レコードレイアウト(データ部)

| # | 項目 | 型・桁 | 必須 | 内容 |
|---|---|---|---|---|
| 1 | レコード区分 | K(1) | ◎ | D固定 |
| 2 | 連携ID | C(20) | ◎ | 経産省側採番の一意キー(冪等性キー) |
| 3 | 取消フラグ | K(1) | ◎ | 0:通常 1:取消(組戻し・誤消込訂正)。取消時は元の連携IDを#4に設定 |
| 4 | 元連携ID | C(20) | ○ | 取消フラグ=1のとき必須 |
| 5 | 事業者番号 | C(10) | ◎ | 機構採番(IF-1oで連携した値を返送) |
| 6 | 納付番号 | C(16) | ◎ | 消込キー(IF-1oで機構が採番・連携した値。§4参照) |
| 7 | 対象申告/決定番号 | C(14) | ◎ | LV-YYYY-NNNNNN |
| 8 | 納付区分 | K(1) | ◎ | 1:本体 2:延滞金 3:その他(協議) |
| 9 | 納付日 | D | ◎ | 収納日。延滞金確定計算の基準日 |
| 10 | 納付額 | N(15) | ◎ | 円。取消時は元レコードと同額(全額取消のみとするか一部取消を許すかは協議) |
| 11 | 収納チャネル | K(2) | △ | 01:振込 02:ペイジー 等(協議) |
| 12 | 予備 | C(50) | △ | |

### 2.2 取込処理フロー

1. ファイル検証(命名・連番・トレーラ件数/金額合計)→ NGはファイル単位で取込保留
2. レコード単位チェック(§2.3)→ エラーレコードはスキップし、正常分のみ取込(部分成功方式)
3. 消込: 納付番号で賦課決定(債権)と突合し、納付区分ごとに充当
4. 状態更新: 未納 → 一部納付 → 完納。**納付額合計 > 債権残高なら「過納検知」**とし還付業務(E-1)のワークリストへ自動連携
5. 延滞金の確定: 納付日をもって延滞金を確定計算(納期限翌日〜納付日。率は政省令待ちのパラメータ)
6. 受信結果応答: 正常件数・エラー明細(§2.3のコード付き)を返送

### 2.3 エラーコード(案)

| コード | 内容 | 機構側の扱い | 想定原因・対処 |
|---|---|---|---|
| E01 | 連携ID重複 | スキップ(冪等) | 再送ファイル。対処不要 |
| E02 | 事業者番号 不存在 | エラーリスト返却 | マスタ同期ずれ。IF-1oの反映確認 |
| E03 | 納付番号/申告番号 不存在 | エラーリスト返却 | 賦課決定前の入金等。保留トランザクションとして滞留管理 |
| E04 | 金額不正(0円以下・桁あふれ) | エラーリスト返却 | 経産省側調査・再送 |
| E05 | 取消対象の元連携ID不存在 | エラーリスト返却 | 順序逆転。翌日便で再送 |
| E06 | 必須項目欠落・型不正 | エラーリスト返却 | フォーマット異常 |

### 2.4 状態遷移(債権側)

```
賦課決定(債権発生) → 未納 ─納付(一部)→ 一部納付 ─納付(残額)→ 完納
                       │                        │
                       └──── 納付額>残高 ────▶ 過納検知 → 還付(E-1)へ
取消レコード受信時: 消込を逆仕訳し状態を再計算(完納→一部納付 等)。還付処理着手済みの場合はアラート(手動判断)
```

## 4. IF-1o 賦課決定情報(機構→経産省)【論点・最重要】

### 4.1 なぜ必要か

収納側が入金を賦課決定に紐づけるには、**請求(いくら・誰が・いつまでに・どのキーで)の事前情報が必須**。納付書発行は対象外だが、「納付書を作らない」ことと「請求情報を連携しない」ことは別問題であり、以下のどちらかを協議で決める必要がある:

- **案A(推奨)**: 機構が納付番号を採番し、IF-1oで賦課決定情報を日次連携。経産省は納付番号で収納受入 → IF-1aで同じ納付番号を返す。**消込が機械的に完結**
- **案B**: 経産省側が独自キーで収納し、機構は事業者番号+金額等で名寄せ消込。**曖昧マッチングが発生し消込エラーが常態化するため非推奨**

### 4.2 レコードレイアウト(案A前提)

| # | 項目 | 型・桁 | 必須 | 内容 |
|---|---|---|---|---|
| 1 | 連携ID | C(20) | ◎ | 機構側採番 |
| 2 | 処理区分 | K(1) | ◎ | 1:新規 2:変更(更正による金額変更) 3:取消(減額更正で0円等) |
| 3 | 納付番号 | C(16) | ◎ | 機構採番。以後の全連携の消込キー |
| 4 | 事業者番号・事業者名 | C(10)/C(120) | ◎ | |
| 5 | 対象申告/決定番号 | C(14) | ◎ | |
| 6 | 賦課金額(請求額) | N(15) | ◎ | 更正時は更正後残高 |
| 7 | 納期限 | D | ◎ | 延納許可(機構側許可の場合)反映後の期限 |
| 8 | 発生事由 | K(1) | △ | 1:申告 2:職権決定 3:増額更正 |

### 4.3 更正・還付との整合

- **増額更正**: 処理区分2で差額分の請求情報を連携(または残高洗い替え。方式は協議)
- **減額更正**: 納付済額が新残高を超える場合、機構側で過納検知→還付(E-1)。**収納側への返金指示は流さない**(還付は機構が全銀IF-5で直接支払うため)。二重返金防止の責任分界を協議で明文化すること

## 5. 非機能・運用

| 項目 | 内容 |
|---|---|
| 監査証跡 | 受信ファイル原本・取込結果・消込前後の債権残高を7年保存(帳簿保存義務に整合) |
| 突合バッチ | 月次で両者の累計収納額をトレーラ合計ベースで照合(残高証明的な突合)。不一致時の調査手順を運用設計 |
| テスト | ①フォーマット疎通 ②サイクルテスト(賦課→納付→取消→過納→還付の一巡) ③大量データ(全事業者一斉納付日) ④障害訓練(未達・欠番・重複再送) |
| 変更管理 | レイアウト変更は版番号管理(ヘッダに版番号を保持し、取込側で版判定) |
