# テスト観点書(ドラフト)

- 位置づけ: 状態遷移定義・IF仕様書・画面モックから導出したテスト観点の一覧。詳細なテストケースは実装工程で本書から展開する
- 前提: 数値パラメータ(単価・利率・期限・閾値)は仮置きのため、**境界値はパラメータ相対**で定義する(例: 「納期限+1日」)

## 1. テストレベルと本書の対象

| レベル | 対象 | 本書の扱い |
|---|---|---|
| 単体 | 計算ロジック・画面部品 | §2(計算)を観点提供 |
| 結合 | 業務フロー内の画面・バッチ連鎖 | §3(シナリオ)を観点提供 |
| システム | 状態遷移網羅・IF・非機能 | §3〜§6 |
| 接続(対外) | 経産省・銀行・法人番号API・NACCS | §5。相手側との**サイクルテスト**が必須 |
| 受入 | 機構業務部門による業務シナリオ | §3の主要シナリオを流用 |

## 2. 計算ロジックの観点(単体)

| # | 観点 | 境界・異常系 |
|---|---|---|
| C1 | 賦課金額 =(数量−控除数量)×係数×単価 | 控除数量=0/数量と同値(全量控除)/数量超(エラー)。端数処理(円未満の丸め方向は政省令待ち→**パラメータ化を確認**) |
| C2 | 単価・係数のスナップショット参照 | 申告後にマスタ改定→申告・還付の金額が**変わらない**こと。過年度還付が納付年度の単価を参照すること |
| C3 | 延滞金 | 納期限当日納付=0円/翌日=1日分。延納許可後は延納後期限基準。取消→再納付の再計算 |
| C4 | 還付加算金 | 起算日(納付日翌日)〜支払決定日の日数。うるう年またぎ。充当がある場合の元本(認容額ベースか充当後か→仕様確認事項) |
| C5 | 充当 | 未納あり: 充当→差額振込/未納≧還付額: 振込0円/延滞金への充当順序 |
| C6 | 決裁閾値 | 閾値ちょうど(5百万円・1億円)は上位・下位どちらの決裁か(仕様明記→境界テスト) |

## 3. 業務シナリオの観点(結合〜システム)

**S1 基本一巡(ハッピーパス)**: 届出→申告→審査承認(債権発生・IF-1o)→納付連携(IF-1a)→消込完納→R02/R03系交付
**S2 過納還付一巡**: 申告確定・納付済→更正の請求(F04)→減額更正(G-4決裁)→過納検知→還付審査→充当判定→加算金計算→支払決定→全銀→支払済(R05・R07交付)
**S3 用途還付一巡**: 納付済申告→用途還付申請(F05・証憑)→審査→一部認容(不認容部分の教示文)→支払
**S4 増額更正**: 職権増額→追加債権の発生→IF-1o変更連携→通知(R04)→納付→消込
**S5 職権決定(無申告)**: 未申告抽出→職権決定→債権発生→通知(R03)
**S6 取消の巻き戻し**: 完納→取消レコード受信→一部納付へ逆仕訳→**進行中の還付が「停止」**→再開/回収の分岐
**S7 延納一巡【候補】**: 申請→担保余力チェック→許可→期限上書き(G-5とIF-1o反映)→期限内完納→担保自動解除。不履行→許可取消・延滞金遡及
**S8 差戻し往復**: 申告差戻し→修正再提出→承認/還付証憑不備→差戻し→再提出
**S9 口座変更と還付の競合**: 口座変更届出が審査待ちのまま支払決定→旧口座使用の確認+90日ルールの追加確認発動
**S10 却下系**: 更正の請求却下(R06・教示文)/用途還付却下/延納不許可

## 4. 状態遷移の観点

- 状態遷移定義.md の**全遷移を1回以上通す**(遷移網羅)。特に: 停止→再開(手動+決裁)、過納検知→完納(還付完了による解消)
- **不正遷移の拒否**: 未確定申告への更正、未納付申告への用途還付申請、二重の支払決定、差戻し中の承認
- 同時操作: 同一申告への同時審査、支払決定と取消受信の競合(排他・後勝ち防止)

## 5. 外部IFの観点(接続テスト)

| # | 観点 |
|---|---|
| I1 | IF-1a正常系: 0件連携/大量(ピーク件数)/複数ファイル(連番) |
| I2 | IF-1a異常系: **エラーコードE01〜E06を各1件以上**。部分成功(正常分のみ取込)。エラーリスト(R11)返却内容 |
| I3 | 欠番・重複: 連番飛び→取込保留・アラート/同一ファイル再送→全件E01スキップで冪等 |
| I4 | 取消: 通常→取消/取消が先着(E05)/一部取消(仕様確定後) |
| I5 | 未達: 定刻+2時間→アラート→手動取込画面での代替 |
| I6 | IF-1o: 新規/変更(増額・減額・延納期限)/取消の各区分が収納側に正しく反映(サイクルテスト) |
| I7 | 全銀(IF-5): 振込データ形式、支払不能の戻り取込→「支払不能」遷移 |
| I8 | 法人番号API: 実在/不存在/API停止時の届出受付(手動審査へのフォールバック) |

## 6. 非機能の観点(抜粋)

- 申告期限日ピーク(同時200セッション・最終3日集中)の負荷試験
- バッチ窓(7:00〜9:00)内の処理完了(ピーク件数で)
- 権限: 起案者=承認者の操作が**システムで拒否**されること。還付支払と口座変更承認の兼務禁止
- 監査証跡: 金額変更・承認・マスタ変更・支払の操作ログが漏れなく記録され、改ざん検知が機能すること
- パラメータ変更: 利率・閾値・期限の設定変更が適用開始日どおりに反映され、**過去データに遡及しない**こと
- 年度切替: 新旧単価の並行期間(3月申告を4月に処理等)で正しい年度の値を参照すること

## 7. テストデータの方針

- モックの一貫シナリオ(〇〇石油: LV-2028-000482 申告821,437,500円/LV-2028-000391 過納12,085,000円→加算金38,738円)を**標準テストデータ**として流用し、ドキュメントとテストの突合を容易にする
- 端数・境界用に素数的な数量(例: 数量7,777.777)のデータセットを別途用意
